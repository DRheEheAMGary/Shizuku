## 液态玻璃折射尝试（2026-10-27）

状态：**未定论，顶栏已先回滚。** 记录到此为止，下一轮接着查。

> 重要更正：早期结论写的是「Chromium 不支持 / 位移无效」，但后来把 glisse 自带的
> 组件（同一个包、同一台机器、同一个 Chrome 155 + Metal GPU）放在高对比条纹背景上，
> 条纹在胶囊边缘**确实被压弯了**。所以问题大概率出在我们这份移植实现，而不是浏览器。
> 已回滚的是「当前这版移植」，不是这个方向。

### 做了什么
移植 glisse（MIT）的 Chromium 路径：canvas 逐像素生成圆角矩形 SDF 位移图 →
`<svg><filter>` 里的 `feImage + feDisplacementMap + feGaussianBlur` →
把 `url(#id)` 写进顶栏的 `backdrop-filter`，另配一张高光图铺成 `background-image`。

### 为什么判定无效
量法：同一页面、同一材质，只切换「滤镜在 / 不在」，逐像素对比胶囊区域。
更关键的一组：把 `feDisplacementMap` 的 `scale` 从 69.8 改成 **0**（完全不做位移）。

| 对比 | 平均通道差 | 说明 |
| --- | --- | --- |
| 无滤镜 vs 滤镜（真实插画背景） | 5.8/255 | 看起来"变了" |
| 无滤镜 vs 滤镜（背后铺高对比条纹） | 52.4/255 | 变化很大，但**是条纹被抹平**，不是被掰弯 |
| **滤镜 scale=69.8 vs scale=0** | **0.10/255** | 位移量对画面几乎没有影响 |

headless（软件合成）和带 GPU 的 headed Chrome（Metal）两边结果一致。
即：Chromium 会把带 SVG 滤镜的 backdrop 先降采样再过滤，于是拿到的是"额外一大层模糊"，
位移映射被压成亚像素级，等于没有折射。视觉上的"玻璃感"其实全来自高光图与半透明底色。

### 下一轮从哪查（省得重来）
1. 拿 glisse 生成的 `<filter>` 和我们的逐属性对比。已知差异：他们末尾多一个
   `feColorMatrix type=saturate`；其余 `filterUnits/primitiveUnits/x,y,w,h` 看着一致。
2. 直接借他们的滤镜验证：把他们的 filter 塞进我们的页面、套一个同尺寸的普通 div
   （不是顶栏，顶栏有 sticky 祖先），看条纹弯不弯——能弯就说明是顶栏的 CSS 上下文
   （祖先层叠/合成层）在作怪，而不是滤镜本身。
3. 顺手验证一个可能性：Chromium 可能在 `backdrop-filter` 链里对带 url() 的情况做
   降采样，导致小位移被抹掉；如果 2 验证滤镜没问题，就要往"换更大的位移/更小的元素"方向调。
4. 测的时候一律用**带 GPU 的 headed Chrome**，别用 headless（两边行为不同，早期误判就源于此）。

### 已经确定的事
- 位移图本身没问题（R/G 通道 3–252，均值 128，和 glisse 生成的图统计一致）。
- 我们的实现里，滤镜**确实被应用了**（挂上后画面变化 5.8–52.4/255），但表现为"背景被抹平"而不是"被弯"。
- 顶栏的材质（84% 白 + 24px 模糊）对折射极其不利；要看清必须调透、调小模糊——这点仍然成立。
